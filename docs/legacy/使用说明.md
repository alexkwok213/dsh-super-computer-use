# 怎么用（非技术版）

## 一次性的两件事

装好后如果系统弹出「"Computer Use"想要控制你的电脑」和「想录制屏幕」两个窗口，点允许就行——这是 App 自己拉起来的授权请求（和 Claude 一样）；没弹就在菜单栏 `● CU` 里点「弹出授权窗口」。

1. **授权**：系统设置 → 隐私与安全性 → 打开“辅助功能”和“屏幕录制”，把**运行它的程序**（WorkBuddy，或你自己开的终端）打上勾。
2. **挂载**：`~/.workbuddy/mcp.json` 里已经有 `computer-use` 这一项（安装脚本会检查）。**重启 WorkBuddy**，然后**新开一个对话**，工具才会出现在这一轮对话里。

不放心可以随时自检：`./bin/cu selfcheck`，它会告诉你权限够不够、有没有被暂停、缺什么。

## 在“应用程序”里找到它

`./install-app.sh` 会把 **Computer Use.app**（显示名 **Computer Use**）装进 `/Applications`。双击它，菜单栏会出现 `● CU`；它故意不占 Dock。重复双击不会开出第二个。

## 让它变成“随时在线”的服务（推荐）

跑一次 `./install-app.sh`（服务和菜单栏都会指向 App 里的引擎），然后在系统设置里给
**Computer Use**（磁盘上 `/Applications/Computer Use.app`）打开“辅助功能”和“屏幕录制”两个开关。

装好后屏幕右上角会出现一个 `● CU`：绿色=一切正常，橙色=服务在跑但还差授权，黄色=被暂停，红色=服务没运行。点它就能暂停/继续、打开设置、跳到系统设置里授权。设置窗口里可以改端口、截图清晰度、是否“你一动就暂停”、是否显示橙色指示条，以及允许控制哪些应用。

之后它就常驻在后台：**任何 AI 应用连它都不需要再单独授权**，你也不用为每个新的 AI 应用重复开权限。想看它是否健康：`curl http://127.0.0.1:47777/v1/status`，看 `nextSteps` 是否为空。

## 日常怎么使唤它

直接在对话里说人话，比如：

- “看看我现在屏幕上有哪些窗口”
- “把微信那个窗口截个图给我”
- “在备忘录里新建一条，写上今天的待办”
- “帮我把浏览器地址栏里的内容改成 xxx”
- “先找到‘发送’按钮再点，别点错”

它会自己走这套流程：列窗口 → 读界面（或截图）→ 找到控件 → 点击/输入 → **再读一次确认结果**。

## 它不会做的事

- **不会抢你的前台**：点击和输入默认在后台完成，你可以同时用别的窗口。只有你（或它）明确要求“调到前台”时才会切窗口。
- **右上角那个小药丸也不抢焦点**：它只是浮在屏幕角上，不会变成“当前应用”，你的键盘鼠标还留在原来的窗口里。（每个新版本编译安装后，菜单栏 App 只由系统在后台启起来，不会把控制台窗口弹到你面前。）
- **屏幕边缘的蓝紫呼吸光只在它操作时出现**：光带只占屏幕最外一圈（约 72pt），停手约 2 秒就淡出，空闲时完全不显示。
- **不该点的时候会停手**：你按了提示条上的 ×（=暂停）、屏幕上开着密码框的安全输入、目标窗口被别的窗口盖住、弹着对话框、窗口在别的桌面……它都会拒绝并在回复里说明原因，而不是硬点。
- **不碰密码框**：安全输入控件一律拒绝。

## 在哪看“谁在用它”

点菜单栏的 `● CU` → **控制台…**，一页看完（2026-11 改版，视觉参考旧版 Claude Computer Use）：

- **概览**：应用图标和标题；**权限**卡片（绿色圆点=已允许，「去授权」会直接跳到系统设置并弹出可拖拽应用的引导浮窗）；
  **本地 agent**列表（Qoder / WorkBuddy / Claude Code / Claude Desktop，每个开关直接写入或移除 MCP 配置，详情写清
  “已配置 / 重启客户端后生效 / 已验证调用”）；最下面是**服务**卡（端口、在线客户端、正在做什么、检测、重启）。
- 底部四个图标：**连接与使用**（谁正连着、最近动作、每个工具耗时）、**诊断**（状态、路径、日志、可复制求助）、
  **设置**（端口、截图大小、一动就暂停、窗口光环、允许控制的应用）、**暂停**（暂停/继续所有电脑操作）。
- 概览右上的「＋ 其他 agent」：给出可直接复制的 MCP 配置，复制后按钮会变「已复制」。

改完设置点「保存并重启服务」，服务会重启一次。控制台关掉后焦点会还给原来的窗口。

菜单栏下拉里也直接显示“客户端：某某 · 刚才 · 点了什么”，不用打开窗口就能瞄一眼。

## 我拿 WorkBuddy 真试了一次

用这套工具去操作 WorkBuddy（腾讯那个 AI 应用）：CU 在**不动你鼠标、不抢你前台**的情况下，点了「新建任务」、把一句话打进了它的输入框、按了发送，然后把它回来的那句「收到这条消息了。」读了出来。整条链路每一步都在 0.2–0.4 秒内。

反过来也让 WorkBuddy 调了 CU：它用自己的终端能力访问本机服务，拿回「当前屏幕上有 13 个窗口」，控制台的「连接」页里就多了一行 `WorkBuddy · http`。

一个诚实的边界：WorkBuddy 这个版本（5.9.3）只把**市场里的连接器**挂进任务会话，我们这种自己加的 MCP 连接器虽然面板上显示「35/35 工具已启用」，但不会进它的工具清单，而且工具是会话开始时一次性注入的、开着会话改不了。所以想让 WorkBuddy 用 CU，目前走本机服务这条路；等它哪天支持自定义连接器注入任务会话，MCP 这条路就顺了。

## 那圈橙色是什么

它开始操作某个应用时，屏幕**右上角会浮出一个小药丸**：写着"应用名 — 自动操作中"，右边一个停止键，和 Claude 那个小指示是一回事。它不会盖住正在被操作的应用、不跟窗口跑、也不抢焦点。点停止键等于让它立刻停手（之后所有动作都会被拒绝，直到你让它继续）。不想要这圈提示，设环境变量 `CU_AUTO_HALO=0`；想要老式的"贴在窗口上的高亮框"，设 `CU_CAPSULE=0`。

药丸随 MCP 操作显示：连续调用之间保留两秒，空闲两秒后自动收起；正常断开连接时立即清理自己创建的提示。下一次操作会重新显示，切换目标时先收起旧提示。用户的文档窗口、浏览器和终端不会因为任务结束而被自动关闭。

开发时优先运行 `bash tests/run_all.sh --quick`：只验证 Python/MCP 逻辑，无须编译 Swift，也不会打开终端或应用窗口。完整的 macOS 界面回归仍使用 `bash tests/run_all.sh`，从现有终端运行，不要为每个测试新开 `.command` 窗口。

## 速度与“不抢控制权”

- 找按钮这类“看字就能判断”的动作不用大模型看图了：先在窗口的控件树里找文字（约 0.2 秒，坐标精确），有控件就直接触发它的动作；找不到才用本机 OCR（约 0.7 秒）。`click_text` 一次调用完成“找到并点下去”，常规界面实测 **0.37–0.40 秒**，只能靠图像时约 1.2 秒。
- 移动/缩放窗口也在后台完成：`move_window` 直接设置窗口位置和大小，不激活、不动鼠标。实测窗口精确位移 +60/+40，前台应用和光标都没变。
- 读文字、粘贴长文本也走后台：`read_text` 先读控件树（约 0.25 秒），`paste_text` 用 AX 插入而不是剪贴板，都不切前台。
- 所有点击/输入默认后台执行：**不移动你的鼠标、不切换前台、不抢键盘**。实测前台是别的应用时点它，前台和光标都保持不变。
- 它只在“必须看图判断”的时候才会让你（或模型）看截图；而且只需要看局部时可以只截那一块（同样的清晰度、体积约五分之一），照片多的界面还能用 JPEG，传输体积再小三分之二。

## 你动手它就会暂停

这是照 Claude 的行为做的：它做完一步之后，如果你动了鼠标或键盘，下一步会**先暂停**并返回“稍后重试”，免得跟你抢操作。继续让它做就行；批量自动化场景可以设 `CU_NO_USER_PAUSE=1` 关掉这个礼貌。

## 常见问题

- **截图是黑的 / 报 capture_failed**：屏幕录制权限没给到“运行它的程序”。现在有三层兜底——引擎自己拍不到时会转给菜单栏 App 代拍；只要菜单栏 ● CU 在跑且有屏幕录制授权，截图和 OCR 就能用。想确认代拍这条路，跑一次 `cu shot --screen --via-app --out /tmp/t.png`。
- **刚重新编译完就"变笨"了**（窗口没标题、截图失败、点不到控件）：系统按程序的身份记授权，换了新编译出来的程序，旧授权就对不上了。到 系统设置 → 隐私与安全性 → **辅助功能 / 屏幕录制** 里，把 `Computer Use`（`Computer Use.app`）用减号删掉、再用加号加回来，然后点菜单栏里「重启服务」。
- **点不动、报 not_frontmost**：那个应用没抢到前台。让它重试；或明确说“可以调到前台”。
- **报 off_stage_window**：开着“台前调度”，目标窗口只是左侧缩略图。按文字点击按钮（控件自带动作）通常仍能后台完成；整窗输入、粘贴、滚动要么把它放到当前桌面，要么在输入/按键/粘贴时加“允许离台尝试”——引擎会真的投递一次并读回应用状态验证，成了才算成功。
- **报 control_disabled**：那个按钮现在是灰的（比如聊天输入框为空时的“发送”）。先让输入框真的有内容，再点。
- **报 paused_by_user**：你之前点了提示条上的 ×。说一句“继续”即可（内部会清掉暂停）。
- **某个界面读不到控件**：那是自绘界面（比如剪映），改用截图 + 坐标点击。
- **双击 App 又弹一个控制台？** 不会——双击已运行的 App 只会把控制台调到前台（和 magpie 一样是“接管”不是“再开一个”）。之前那个「应用程序不再打开」的报错已经修掉：根因是后台服务进程顶着 App 包里的同名程序，系统把它当成了 App 本人。现在服务跑的是包外的一条硬链接，和 App 共享同一份引擎，但不再冒领身份。
