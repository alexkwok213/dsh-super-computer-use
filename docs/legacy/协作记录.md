# CU 项目共享经验与待办

本文件供多个 AI 和开发者交接。记录区分现场事实、代码改动和待验证假设；不要把工具返回 `ok` 当作应用已完成操作。记录最近一次状态，不代替重新检查代码与运行环境。

## 目标与协作方式

目标是在保证目标和结果准确的前提下，缩短从接收任务到执行完成的时间。优先测量端到端耗时、工具往返和误操作率，再决定引入什么组件。

多人或多个 AI 同时工作时，先在共享渠道声明正在修改的文件和范围；不要让多个写入者同时改同一文件。每次完成一项工作，在下方追加日期、涉及文件、验证方式、结果及限制。运行中的 MCP 进程可能仍加载旧 Python 代码；文件已部署并不证明现有会话已更新。不要记录 token、剪贴板内容或无关的私人数据。

提交与推送 GitHub 前，按 [GITHUB同步.md](GITHUB同步.md) 执行：其中写明哪些本地改动永不暂存、提交前如何净化本文件、推送命令与远端 SHA 校验。

## 优先优化与验证

1. **建立基线**：对同一个任务记录总耗时、每次工具调用开始/结束、AX 遍历与序列化耗时、截图耗时、等待应用耗时、重试次数；区分模型思考/网络/客户端耗时，不能从动作日志间隔推断。记录样本数、环境、结果和失败情况。
2. **可靠多选**：在独立可控的测试文件夹或测试应用里验证列表焦点、选中元素数量与名称，比较 Cmd+A、范围选和 AX 选择等方式。通过可读的选中状态验证后再用于剪映；只有明确选中目标文件才提交导入。
3. **精简观察和减少往返**：按需读取当前窗口、目标控件、焦点和选中状态；确定性的动作可尝试 `batch`，在关键状态变化处验证。测量速度、结果正确率和误操作，而不是只减少工具调用次数。
4. **截图端到端复现**：在解锁状态用真实目标窗口测试 service 与 MCP 的捕获和返回，确认图片内容有效，记录授权身份、进程版本和耗时；不要声称黑图是成功。
5. **回归安全性**：覆盖窗口目标、模态、焦点变化、ref 重用和跨窗口误指；验证失败时停止而不是盲点。必要时回退有风险的实现。
