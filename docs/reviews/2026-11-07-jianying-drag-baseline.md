# 剪映界面操控基线：2026-11-07

## 目标与边界

在同一台 Mac 的剪映专业版中，使用 DSH `cu_*` 工具新建独立草稿、导入白模和 Seedance 2.0、放到独立轨并对齐 0 秒、把第二条缩放设为 50%，检查音量。此试验不使用草稿写入、FFmpeg 合成或其他鼠标工具；它是四宫格完整验收前的两个片段测试。目标不是已达到 Codex 水平的证明。最终不导出视频。

## 运行环境和干预

- DSH 模型：DeepSeek-V4.1-Flash · WorkBuddy，High；本机 linked 插件 0.8.0，开发中 Host `43661c12de63…`（尚非发布版）。
- 测试草稿：剪映「11月7日 (2)」，两个素材来自 OPCroad `01-内容项目/2026-11 AI模型效果对比`。
- 用户授权测试期间使用前台键鼠。验收 Agent 获得两次人工补充：可通过窗口关闭按钮返回首页；AX 快照节点坐标已是屏幕逻辑坐标，不要再加窗口原点。因此这不是无干预基准，也不是同条件 Codex 对照。
- 约 13 分钟，92 个步骤；该时间包含探索、反复截图、两次干预和验收收尾，不是独立工具的耗时。

## 观察到的结果

- 两次后台 `cu_drag` 尝试后，Agent 报告时间线未变化，并用截图复核；该情形不支持声称后台有效。不能由两次结果推断所有坐标、剪映版本或后台策略均失败。
- 前台 `cu_drag` 将两段素材分别放到剪映两条轨道；第二段起初偏离 0 秒，首次纠正手势移动了播放头。经提示 AX 坐标语义后，Agent 将第二条从屏幕 x=217 拖至 x=197，两个片段左边缘对齐。Agent 报告前台拖入分别约 2424 ms 和 1409 ms，最后一次对齐约 1267 ms；这些是单次工具报告，并非延迟分布。
- Agent 通过剪映参数面板将 Seedance 缩放设为 50%，报告两段音量均为 0 dB。独立观察剪映时，测试草稿可见双轨、左边缘视觉对齐、白模上叠加缩小的 Seedance 画面，当前选中片段音量面板显示 0 dB。没有独立检查每个片段的精确时间码、听感或导出。
- Agent 报告 `cu_session stop` 返回 `cleanupState: unknown` 与 `restoredTarget: false`；不能将其表述为清理或恢复成功。
- Agent 曾把 AX 快照 `@x,y` 当成窗口相对坐标并额外加窗口偏移，出现错误落点。该误解有实际操作和源码证据；但不能单凭本次证明此前所有坐标失误都有同一原因。

## 后续同题比较

同一初始窗口尺寸、素材与目标，分别记录模型/工具版本、实际图像是否送达、用户干预、每次操作及后置证据、端到端耗时、失败/重试、最终位置/时间/音量、停止与清理状态。后台和前台分开报告；包括窗口变化、弹窗、取消与恢复。完整任务应扩展到四宫格、裁切、标签、播放和保存重开，并由独立观察者检查真实剪映画面。此前 Codex 坦克草稿由脚本生成，不能作为纯界面操控同题耗时对照。

## 原生前台拖拽边界回归

`python3 engine/tests/drag_guard_live.py` 会临时创建空白窗口并使用真实鼠标事件，适合有桌面会话时手动运行，不适合无人值守测试。修复前实测：传入与窗口不匹配的 pid，或将终点设在窗口外，原生引擎仍返回成功。修复后使用临时编译的引擎验证：错误 pid、窗口外起点或终点均被拒绝，空白窗口没有收到鼠标事件；有效拖拽收到按下、拖动和释放。此测试不证明剪映业务动作落地，也不覆盖透明 halo、模态窗口或中途焦点变化。

随后在相同空白窗口复现：halo 的透明边框被误识别为遮挡。扩展的真实窗口测试验证有效拖拽穿过透明边框，28 点高的停止按钮仍被判为遮挡，独立进程的真实遮挡窗口也被拒绝。识别边框需要同时匹配本引擎的进程路径、目标窗口几何以及同进程的停止面板；任一条件不匹配时不会忽略窗口。测试未覆盖模态窗口或拖动中途的焦点变化。

## v0.10.2 剪映四宫格验收中止与顶部边界

DSH 在保持 halo 开启的情况下创建独立空白草稿「11月7日 (4)」，但素材尚未导入时，坐标点击仍被 halo 的窗口 7513 拒绝。验收约 4 分 19 秒、34 步；其间独立测试窗口短暂占用前台，且后来向 Agent 发送了停止指令，因此不是无干预基准。Agent 报告 stop 返回 inputGateClosed: true、remainingTargets: 0、cleanupState: unknown、restoredTarget: false；四宫格、音频、播放和保存重开均未完成。

实测剪映窗口靠近屏幕顶部：目标 y=43，halo y=33，停止面板 y=49；这与理想的 12 点边框偏移及控制面板位置有 2 点误差。加入贴近顶部的空白窗口场景后，v0.10.2 重现了误拦截；允许 3 点几何误差后，顶部和普通位置的测试均通过，停止按钮仍受保护，普通位置的独立进程遮挡也被拒绝。这是本机窗口测试，仍需在实际 DSH/剪映中重新验证。

## v0.10.3 剪映四宫格首轮实测与剩余阻碍

在保持 halo 开启的草稿「11月7日 (4)」中，前台点击和拖拽不再被透明 halo 边框误拦截，Agent 成功通过文件选择器导入 4 段坦克视频并铺上 4 条视频轨道，将白模视频缩放到 50% 且位置设为 `X=-480, Y=-270`。但独立截图与日志复核暴露出三项未完成或阻碍点：

1. **轨道未严格对齐 0 秒**：尽管 Agent 声称 4 轨对齐在 0 秒，独立快照显示主轨 `MTLSVideoP:白模视频.mp4` 位于 `x=153`，而上层 3 条轨道位于 `x=207..257`。
2. **幂等数值输入触发 `type_not_landed`**：剪映位置框点击后暴露 `AXTextField`（如 `automationfirstTextInput`），当框内值已等于目标文本（如 `-480`）时，全选粘贴后 `focusedValue(pid:) != before` 为 `false`，触发二次 `typeText` 并返回 `type_not_landed` 中断批处理。
3. **Halo 停止胶囊遮挡窗口左上角控件**：300×28 停止面板原先固定在 `frame.minX + 16, frame.minY + 18`，直接盖住剪映左上角红黄绿与返回主页按钮区域。

针对第 2、3 项，引擎增加 `hasTypeLanded`（当输入后文本已等于目标值或去除常见单位后相等时判定已落地，不再二次输入或报错）并将 Halo 停止胶囊移至顶部边框水平居中（避开窗口左上角与右上角工具栏按钮），经 `drag_guard_live.py` 与剪映实测通过后进入下一轮完整四宫格验收。

## v0.10.4 四宫格与字幕实测：同列轨道部分遮挡与检查器越界

在 `v0.10.4` 对草稿「11月7日 (4)」的四宫格与 4 条字幕验收中，全程 `service.log` 零 `type_not_landed`、零 `another_window_on_top`；4 条视频轨道（`白模视频.mp4`、`seedance2.0.mp4`、`seedance2.0fast.mp4`、`seedance2.0mini.mp4`）左边缘全部对齐在 `x=165, w=903`（`00:00` 至 `00:06:02`）且原声保留，4 条文本轨道均已改为目标文案（`原始白模`、`Seedance 2.0`、`Seedance 2.0 Fast`、`Seedance 2.0 Mini`）。独立复核发现两处因剪映 Qt AX 树未裁剪遮挡导致的坐标偏差：

1. **同列时间线轨道被底部主轨半遮挡**：当时间线同时存在 8 条轨道时，`MTLSVideoP:seedance2.0.mp4`（`y=926, h=52, cy=952`）的下半部（`y=943..978`）被底部粘性主轨 `MTLSVideoP:白模视频.mp4`（`y=943, h=73`）覆盖。点击未裁剪中心点 `(616, 952)` 实际命中 `白模视频.mp4`，导致 `白模视频.mp4` 的坐标被覆盖为 `(480, 270)`。
2. **右侧检查器未滚动时坐标伸入下方时间线**：选中文本片段时，右侧属性面板可视区止于 `y=556`（`AXScrollBar` `y=172, h=384`），但未滚动前 `automationpositionValue` 仍报告屏幕坐标 `(984, 832)`，实际落点位于下方时间线区域，点击该点会选中时间线片段而非激活输入框，紧随其后的 `Cmd+A` 进而触发全选时间线轨道。

针对这两类 Qt AX 假暴露，`snapshot` 新增同列等宽兄弟轨道遮挡裁剪（自动把 `seedance2.0.mp4` 暴露高度裁为可见条带 `y=926, h=17, cy=934.5`）与检查器越界 `occluded` 标记；同时 `--ref` 坐标点击新增 `AXUIElementCopyElementAtPosition` 命中点自愈与 `element_occluded` 拦截，并在点击响应中返回实际命中的 `hit` 角色与标题。
