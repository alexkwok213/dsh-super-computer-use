# Codex 风格的后台控制与预览设计

## 目标与证据

以用户提供的两段 2026-11-06 录屏为视觉参考。Codex 录屏可见独立的小尺寸目标画面；DSH 录屏中目标移到聊天窗口后，目标的轮廓仍覆盖在前景窗口之上。用户还要求预览可拖动、平时只显示画面，并参考 Codex 的动态效果。视频可见效果不能证明 Codex 的内部实现，也不能单靠录屏证明后台操作可靠性。

当前 `runHalo` 使用 `.statusBar` 和 `orderFrontRegardless()`，因此目标即使被其他窗口遮挡，框线与停止条仍可能压在其他窗口上。DSH 的 `TargetFloat` 是页面内的控件，默认是状态条并须展开才能看到预览；既不能在桌面自由移动，也不等同于独立原生浮窗。仓库虽有 `cu preview` 原生窗口，但目前带标题栏和醒目的边框，不能直接视为已经接入主会话的 Codex 风格浮窗。

## 行为设计

1. 框线跟随具体目标窗口的遮挡关系：目标露出的部分才显示对应框线；被其他窗口盖住的部分不得穿透前景窗口。窗口移动、改变尺寸、隐藏、关闭、切换 Space 时同步处理。不激活或提升目标窗口，不改变用户当前工作窗口。先用真实的跨进程层级实验验证系统能力；若无法可靠将透明面板相对于目标排列，则隐藏不可靠的框线并明确报告，不能伪造正确层级。
2. 每个正在观看的目标使用一个插件管理的原生非激活预览窗口，默认画面为主体、无常驻标题栏或状态文字，保留圆角、阴影与适度出现/消失过渡。可从画面拖动，在屏幕可见范围内放置；拖动不激活目标或移动真实鼠标。悬停时显示最小化的可访问控制（停止、关闭预览）；停止控制仍可从 DSH 原有会话入口访问。无画面、过期、权限或捕获失败时必须明确标识，不能把旧图当实时图。
3. 操作效果以录屏可确认的视觉语言为参考：将移动和点击反馈显示在对应目标的预览坐标中，轻量、短暂、不遮挡内容，并尊重系统减少动态效果设置；未观察到或无法验证的细节不宣称与 Codex 完全一致。按目标、会话、代次隔离反馈，过期事件和目标切换后的旧帧不得串到新目标。
4. 同一聊天的多个目标各自拥有独立预览、位置、捕获与停止状态；其他聊天不得接管目标。关闭预览仅关闭该预览和捕获，不停止控制；停止对应目标则回收其窗口和捕获。最后一个目标结束、宿主断开或重载时回收插件拥有的子进程与窗口。避免默认创建重复的网页和原生预览流。

## 实施边界

复用现有插件管理的 helper、ScreenCaptureKit 捕获、目标身份和会话生命周期；不修改 DSH `app.asar`，不新增无认证端口、不创建插件管理之外的常驻服务。保留当前未提交的多目标工作。对目前仅在 DSH 网页中的控制卡进行必要调整，避免与原生预览重复；保留现有会话控制和失效状态。捕获权限、受保护窗口或窗口最小化导致不可用时按实际状态降级。

## 验收

- 用两个临时目标和第三个前景应用验证：目标部分或完全被遮挡时，框线不覆盖前景应用，恢复前景后正确跟随；移动、缩放、隐藏和结束均正确清理。
- 实机核对预览在不同应用前可拖动、显示对应目标画面，画面比例正确，点击反馈位置与目标对应，窗口失效时状态真实；关闭预览和停止目标各自作用正确。
- 两个目标同时工作，单独拖动、关闭预览和停止其中一个，另一个持续运行；不同聊天的所有权不串扰。验证宿主断连、重载和 helper 退出无残留。
- 为层级决策、代次/坐标映射、生命周期和拖动行为添加有意义的回归检查；运行完整测试和 `npm run dev:sync`。只有命令退出 0 且输出 OK 才报告真实 DSH 运行版本已更新；另行记录实机视觉验收，不能以自动测试代替。

## 实施前需处理的现有接口差距

- 现有 `PreviewChild` 只持有一个进程和窗口，切换目标会关闭旧进程，不能直接承担多目标。新接线必须以聊天、CU 会话、目标及目标代次标识每个预览，命令和退出事件按该身份路由，避免旧进程退出清理新预览。
- 现有原生预览的子进程输出未用于会话控制，而全局 pause 可能影响所有目标。原生浮窗的停止操作需要通过受管理的双向通道携带目标身份回到 Host，复用按目标停止路径；EOF、崩溃与关闭预览均需分别处理。不可用全局 pause 冒充单目标停止。
- 现有原生显示流没有与动作事件对应的帧身份和实时几何。预览效果必须绑定会话、目标代次和几何版本，使用捕获内容矩形及等比例 letterbox 映射；几何变化或帧、事件身份不匹配时隐藏指针直到重新匹配。
- 自动展示预览会启动屏幕捕获并可能触发系统授权提示，是现有默认仅在展开或 Watch 时捕获的行为变更。设计拟在活动目标建立后展示预览；用户关闭后不自动重开，捕获不可用时显示明确状态并允许关闭。
